# Generate the application catalog from per-app registration sidecars

MHK10's application catalog was a hand-maintained array in `src/data/app-catalog.ts` that had to stay in lockstep with the application implementations; boot-time reconciliation only surfaced drift as throws, and tier-2 maps that copied catalog facts (icon files, Start-menu lists, file associations) drifted silently. Each Canvas application now authors its registration facts (id, name, icon key, route, window geometry, menu placement, desktop shortcut hosts) in a zero-import `src/lib/apps/<feature>/<id>.registration.ts` sidecar beside its implementation, and `scripts/generate-app-catalog.mjs` compiles every sidecar into the zero-import snapshot `src/data/app-catalog.generated.ts` (`npm run generate:app-catalog`). The authored `app-catalog.ts` stays the public face: it adds the eight `NON_CANVAS_APPS` seed entries, curates the `CATALOG_ORDER` sequence behind Start-menu order, cascade positions and registry output, and owns `CatalogApp` plus the projection functions. `appMetadata(id)` is deliberately retained as the single icon-key-to-sprite-name seam, because `Application.icon` mixes conventions (catalog apps use `app_<id>` sprite names while shell built-ins such as `$run` and `$find` pass system sprite names like `i_find` directly), so no application module had to change.

Keeping the hand-maintained catalog as the single source and adding the missing fields there was rejected: the facts would remain far from the implementations that change them. Describing modules fully in place, with implementations importing their sidecars directly, was rejected too: the mixed sprite-name conventions mean a mapping seam must exist anyway, and editing all application modules risks colliding with concurrent in-flight work.

A freshness test re-runs the codegen in-process and fails on a stale snapshot or an ordering that misses or duplicates an id; `src/lib/apps/index.ts` keeps excluding `*.registration.ts` from discovery and remains the bidirectional reconciliation safety net. Adding a Canvas application is now a sidecar, an implementation and an icon key (`app-catalog.icons.test.ts` gates both icon sizes), with `npm run generate:app-catalog` after sidecar edits. The `metadata-stays-build-safe` rule is untouched: the snapshot has zero imports, so `src/data` still never depends on `src/lib`.
