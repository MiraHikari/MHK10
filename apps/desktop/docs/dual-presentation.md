# 通用版与 Win95 版融合

MiraHikari 的站点有两个呈现：通用版适用于移动、触屏和普通浏览；MHK10
Win95 版为桌面用户提供窗口、像素图形和应用体验。二者保留自己的布局、字体、
交互与构建依赖，连接同一批个人内容和访客阅读数据。它们是相辅相成的两种
表达，而不是互相替代。

## 内容与地址

内容标识不依赖窗口坐标或展示标题。文章使用 slug，项目使用项目 ID，图片使用
media ID；介绍、技能、图库、友链等使用固定目的地。协议的两端把这些目的地转换
为各自路由。文章、项目深链和正常浏览器历史仍可独立访问。标签是稳定目的地：
通用版使用 `/blog/tag/<标签>/`，桌面版使用 `/blog/?tag=<标签>` 并渲染同一过滤
结果。桌面文件和虚构剧情不会改变公开个人内容。

`packages/site-core/content` 是唯一的事实来源：

- `profile.json` 保存个人资料、介绍、技能、荣誉、经历、友链和 31 个图库项；
- `projects/*.md` 保存 8 个项目卡片与完整项目笔记；
- `blog/*.mdx` 保存 3 篇公开文章；
- `projects.generated.json` 是从项目 Markdown 生成的浏览器安全投影。

`npm run content:align` 从这些作者源生成桌面文章正文、`article-photos.json`、
`projects.generated.json`、桌面资源清单和 `/images/` 图片副本；
`npm run content:check` 只检查漂移。通用版通过 Astro content collections 读取同一批
Markdown；`apps/general/src/data/profile.ts` 与 `apps/desktop/src/data/profile.ts`
只做各自的字段适配。桌面 `src/data/portfolio-presentation.json` 只允许改变语气、
标签、排序、精选和版本说明，不能复制共享事实；加载时会拒绝覆盖共享字段或引用
不存在的记录。通用版管理端只写入 `packages/site-core/content` 中的作者路径，
生成投影不在其写入白名单内。

图片记录保留 `/images/…` 的共同身份，Win95 本地发布目录 `/images/…`
由图片 Adapter 转换；CDN 使用原有 `/images/…` 对象键。通用版的
`apps/general/public/images/` 是 R2 同步源，不进入 Git；桌面 `/images/`
副本由生成器维护并在没有源图的新检出中按清单哈希校验。Giscus、R2 凭据和
管理凭据不进入共享内容。

## 切换与生命周期

通用版是顶层宿主。首次进入 Win95 时加载配置的桌面地址；桌面文档在 POST/splash
开始时发送 `startup`，宿主据此揭示桌面自己的启动动画，并停止绘制 host 侧
Loading。之后等待 `ready` 完成目标内容与焦点交接。iframe 内的窗口会话跨切换
保留；返回通用版传递当前个人内容目的地。隐藏的呈现禁止键盘与指针交互，并
暂停音频、帧循环与启动序列。切换动画遵守减少动态效果偏好，快速反向切换取消
旧操作；启动失败返回仍可阅读的通用版。手机首次显式进入桌面会先提示体验可能
降级，并默认推荐留在通用版；确认后仅当前会话不再重复询问。

新建桌面会话默认播放完整 POST 与 splash；已有访问标记不会省略这段启动。
已明确保存的「仅首访」或「跳过动画」设置继续生效，Welcome 完成标记只控制
介绍窗口是否再次出现。切回仍在运行的 iframe 恢复原会话及其转场，不重新启动。

设备默认规则由通用版在 hydration 前决定：任何设备、任何路由在无偏好时都先
渲染通用版；`/` 上至少 1024 CSS 像素且精确指针的设备会在 Hero 旁看到桌面推荐，
接受后才进入 Win95 并写入偏好；手机、粗指针和 Save-Data / 2G 只看到一行切换
提示；已保存偏好跟随所有路由（包括深链）；`?view=classic|win95` 始终优先。
访客可随时使用右缘切换、命令面板或桌面开始菜单的 **Classic Site** 返回。

融合桌面加载后先暂停并静音，合法父页面握手或恢复指令才唤醒。内容就绪后
宿主明确恢复已经揭示的启动画面；取消时仍在下载的文档不会在后台自动启动。
就绪条件要求真实目的地、可交互文档和 Reader / Profile 的语义就绪标记，
非关键图片不阻塞进入。隐藏或零尺寸的阅读器保留已有进度，可见后再重排；
文档重载重建握手，隐藏重载不会把通用站抢走。

跨源消息验证协议版本、会话、递增请求号、精确 origin、实际父/子 window 和
负载结构。允许交换的数据只有内容目的地、阅读数据和呈现生命周期指令。
管理凭据、AI 密钥、访客文件、图片音频二进制和剧情不进入这个协议。
阅读同步 lane 在拒绝或 8 秒确认超时后释放待发快照，下一次本地修改可以重试；
不会用默认 notebook 覆盖损坏或未来版本数据。桌面文档在暂停期间由
`<html data-presentation-suspended>` 标记，恢复或重新握手时清除；焦点只在
呈现可见且 `inert` 解除后移入 iframe。

访问计数由顶层文档拥有，嵌入桌面与内部 HTML 窗口不再重复计数。

## 保存边界

| 数据                           | 保存策略                                          | 切换/重置                                       |
| ------------------------------ | ------------------------------------------------- | ----------------------------------------------- |
| 公开个人内容                   | 构建期共享事实与原始媒体                          | 两版按稳定 ID 访问；访客无法修改                |
| 阅读进度、书签、批注、阅读偏好 | 带版本号的 notebook；两端各有持久镜像             | 信任协议同步本地改动；按字段/批注 ID 三方合并   |
| 桌面偏好、图标、文件关联       | 兼容现有 `doom95.*` 键                            | Win95 专属；文档重置不删除偏好                  |
| 我的文档                       | revision/epoch 控制的文件目录；二进制在 IndexedDB | 完整 JSON 备份包含二进制；成功提交后才重置/导入 |
| 剧情检查点                     | 独立 `doom95.story.v1`                            | 重放剧情保留访客文档和阅读记录                  |
| 凭据                           | 所属应用独立保存；AI 密钥显式选择记忆             | 不参与跨版同步或文档备份                        |
| 计数与一次提示                 | 本地去重/会话缓存                                 | 不作为用户内容同步                              |

Reader 每次保存对比会话基线、当前编辑与最新持久数据。不同文章、不同批注和
不同偏好字段合并；同一字段的冲突保留会话编辑并显示导出/恢复提示。损坏或未来
版本数据保留原文，不能用默认 notebook 覆盖。通用站高亮按 note id 增删，保存
`block` 块锚点；桌面 `offset` 始终是正文全局 UTF-16 偏移。锚点必须与引用匹配，
失效后按引用定位。不可渲染、跨块、纯文本与超长笔记保留；达到 128 条时拒绝
新增。共享笔记本是偏移与笔记的唯一所有者；退役的通用站高亮缓存被忽略，
不再作为恢复来源（有意不迁移旧数据，旧键数据可以丢弃）。
旧像素滚动值只用于首次测量后的转换，不当成百分比。

无保存偏好时两端宽度默认 comfortable。共享笔记本是偏好的唯一所有者，
退役的通用站旧行宽/专注键被忽略、不再镜像；偏好和笔记分别订阅选择切片。进度更新不重建高亮或恢复滚动，
位置仅在挂载与明确切换返回时恢复。桌面 `doom95.*` 身份集中在
`src/data/storage-keys.ts`，Reader key 由 site-core 的 `reading-storage.ts` 拥有。

两个站点位于不同 origin，浏览器无法直接读取彼此 localStorage。跨源同步需要
配置的可信 iframe 在当前浏览器中同时运行；没有访客账号或云存储，不承诺跨
设备或不同浏览器同步。localStorage 的同步比较避免顺序执行的旧快照覆盖；它
不是跨进程数据库事务，真正同时写入仍受浏览器存储模型限制。

我的文档导入先验证全部文件和二进制，再用新 asset ID 保存二进制，最后提交
目录。失败时保留现有文件与编辑器 epoch，清理本次暂存二进制。成功清空回收站、
重置或导入时才释放已无引用的旧二进制。备份包含回收站和可导出的会话副本；
丢失的二进制会明确阻止生成不完整备份。

## 配置与验收

通用版 `PUBLIC_DESK_URL` 为桌面部署地址；留空时 Win95 模式整体旁路。
Win95 的 `PUBLIC_PARENT_ORIGINS` 是逗号或空格分隔的精确可信源列表；旧
`PUBLIC_PARENT_ORIGIN` 仍兼容。`PUBLIC_GENERAL_URL` 是独立访问桌面时返回
通用版的地址。开发环境必须显式包含实际端口，不能使用任意 origin 通配符。

例如通用版 `http://127.0.0.1:4321`、Win95 `http://127.0.0.1:4322`：

```text
通用版 PUBLIC_DESK_URL=http://127.0.0.1:4322
Win95 PUBLIC_PARENT_ORIGINS=http://127.0.0.1:4321
Win95 PUBLIC_GENERAL_URL=http://127.0.0.1:4321
```

从仓库根目录运行 `npm run dev` 同时启动两版；`npm test` 覆盖共享融合模型；
`npm run test:e2e` 运行桌面 Chromium 场景，`npm run test:e2e:fusion` 用两个真实
origin 检查默认呈现、双向切换、深链交接和阅读数据往返。截图与录制属于
`artifacts/` 或测试报告，不能用静态截图代替运行中的界面。

生产故障与恢复场景见 `tests/fusion/production-readiness.spec.ts`。通过
`MHK_FUSION_BROWSER` 可选 Firefox 或 WebKit；生产配置、CSP、缓存与性能采样
的验收方法见 [通用版部署说明](../../general/docs/deployment.md)。
