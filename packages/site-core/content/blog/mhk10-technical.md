MHK10 是 MiraHikari 的个人站点，也是一张可以真正操作的像素桌面。个人介绍、项目档案、技术栈、照片与文章都能直接通过独立网址打开；与此同时，桌面外壳把这些内容与计算器、画图、纸牌、终端、磁盘整理等本地系统工具放进同一套窗口、菜单、快捷方式和任务栏里。这篇技术说明记录截至 2026 年 10 月 10 日的架构设计与工程实现。

## 为什么保留两种界面

程序的呈现方式由任务决定。计算器、时钟和任务管理器的状态有限、布局紧凑，适合用 Canvas 绘制。它们共享像素字体、边框、选中颜色和输入规则，操作时不需要在两套视觉系统之间切换。

文章、个人资料和相册使用 Astro 生成的 HTML。长段落需要标题结构、文字选择、链接、图片说明和浏览器的阅读能力；这些内容也需要被搜索引擎直接读取。HTML 页面既能独立访问，也能嵌入桌面窗口。较复杂的表单和阅读工具同样使用原生控件，并通过主题变量对齐桌面的外观。

为了避免混合窗口出现“画布与网页割裂”的常见问题，桌面层在三处做了统一收口：

1. **窗口遮挡与几何剪裁**：嵌入窗口由窗口管理器按逻辑客户区坐标定位。当上方存在更高层级的 Canvas 窗口、下拉菜单、气球提示或任务栏时，`html-windows` 通过 SVG 矩形差集路径动态剪裁下层 iframe 的可见与可点击区域，被完全遮挡或最小化的页面自动进入惰性状态。
2. **统一像素指针层**：原生 iframe 光标在进入混合模式后统一隐藏，由顶层透明指针画布绘制 1-bit 像素箭头、沙漏与文本光标，保证鼠标跨过窗口标题栏与内嵌文档边界时不会闪烁或断裂。
3. **共享混合控件库**：HTML 窗口内的工具栏（`Toolbar`）、菜单栏（`MenuBar`）、标签页（`Tabs`）、树视图（`Tree`）、状态栏（`StatusBar`）和下拉框（`Select`）均消费由同一份调色板生成的 CSS 变量与整数像素尺寸，支持单 Tab 停靠点与方向键漫游。

| 界面模式             | 适用场景                                              | 代表应用                                                                    | 核心优势                                             |
| -------------------- | ----------------------------------------------------- | --------------------------------------------------------------------------- | ---------------------------------------------------- |
| **Canvas 即刻模式**  | 状态有界、像素动画密集、强几何约束的系统工具          | `My Computer`、`Notepad`、`PIXEL.EXE`、`Diagnostics`、`Defrag`、`Solitaire` | 逐像素命中测试、16 色抖动、零 DOM 布局抖动           |
| **Hybrid HTML 模式** | 需要长文排版、表单交互、原生选区与独立 SEO 路由的内容 | `Home`、`MiraHikari — Properties`、`Device Manager`、`Reader`、`ACDSee`     | 语义化标题与大纲、无脚本可访问、搜索引擎与阅读器友好 |

新增应用时，先判断内容和交互需要什么，再选择 Canvas、HTML 或二者配合。这里的混合渲染，是让窗口与内容各自使用合适的工具。

## 五层视觉语域与启动序列

一台 1995 年前后的个人电脑并不是单一扁平的 GUI：向下可以看到固件自检与 DOS 文本终端，向上则是多媒体光盘界面与早期万维网。MHK10 将这套年代层次整理为五层视觉语域（Register Stack），每层拥有明确的调色板子集、字体、边框语法与叙事职责：

| 语域层级             | 年代参照 | 视觉与排版规则                                                       | 声音反馈       | 系统中的职责与场景                                                        |
| -------------------- | -------- | -------------------------------------------------------------------- | -------------- | ------------------------------------------------------------------------- |
| **L0 FIRMWARE**      | 1981–94  | 纯黑底色、CP437 框线、仅限黑/白/银/灰/亮绿五色、`dos` 8px 字体       | 单频蜂鸣       | **事实层**：BIOS/POST 启动自检、真实宿主环境报告、99.9% 终局固件控制台    |
| **L1 TEXT-MODE TUI** | 1988–93  | 海军蓝底、青色双线框、黄色热键、阴影面板、`dos` 8px 字体             | 机械键击       | **诊断层**：`Diagnostics` 信号终端、高风险阶段下的 `Recovery` 与 `Defrag` |
| **L2 CHICAGO GUI**   | 1995     | 经典立体斜面（bevel）、16 色 VGA 调色板、`ui` 11px 与 `MHK CJK` 12px | 系统事件音     | **日常层**：桌面外壳、窗口管理、文件管理器、个人属性页与混合应用          |
| **L3 MULTIMEDIA**    | 1995–97  | WordArt 艺术字、彩条、Bayer 抖动色带、整像素动画                     | 三声部和弦     | **情绪层**：Splash 启动画面、屏幕保护程序、媒体播放器频谱与结局演出       |
| **L4 WEB 1.0**       | 1996–99  | 早期超文本布局、蓝色下划线链接、独立拨号沙盒                         | 调制解调器握手 | **外部层**：`Dial-Up` 拨号连接打开的早期个人主页与访客留言簿              |

### POST 自检与 Splash 启动动画

首次进入桌面（或在设置中开启每次启动动画）时，系统依次经过 **L0 POST 自检** 与 **L3 Splash 启动画面** 两个阶段：

- **L0 BIOS/POST 阶段**：遵循“L0 从不捏造虚假硬件参数”的原则，`boot-info` 只读取并格式化浏览器真实上报的宿主信息（UA-CH 品牌与版本、平台、语言、逻辑线程数、CSS 视口尺寸与 DPR），绝不虚构不存在的处理器型号或内存容量。画面在双线 CP437 框线与像素固件徽章下逐行输出宿主环境，并分四步校验画布显示桥接、键鼠路由、本地持久卷挂载与叙事检查点，配合底部离散进度格与实时 POST 状态码完成自检。
- **L3 Splash 阶段**：自检完成后切入多媒体启动卡片。画面随当前所选主题（如标准青色、Singularity Night、Hot Dog Stand 或 Phosphor 单色绿显）渲染抖动天际线、VGA 彩条、开始徽标、WordArt 立体标题与底部流动光带，随后平稳揭示桌面工作区。按下任意键、点击屏幕或开启系统的 `prefers-reduced-motion` 均可快速跳过或缩短等待。

## 个人介绍的设计：把履历放进桌面隐喻

传统个人作品集往往把所有卡片堆叠在一条长滚动页面里；而在 MHK10 中，个人介绍被拆解成三组彼此联动、符合经典桌面直觉的系统组件，所有数据均由 `src/data/profile.ts` 与 `portfolio.json` 单一事实源驱动：

### 1. Home：三栏式个人资源管理器

`Home`（`/`）是进入桌面时的默认焦点窗口，采用资源管理器（Explorer）的三栏工作区结构：左侧为文件夹树（`Home`、`Projects`、`Recent`），中间为对象列表，右侧为即时属性预览窗格（`Selection details`）。

- **选择与打开分离**：单击列表项或用方向键移动焦点时，右侧预览窗格立即展示该条目的身份铭牌、缩略图、简介与特性标签（例如选中 `About` 时展示头像、所在地与五项核心专长，选中具体项目时展示项目画面与技术栈标签），而不会直接跳转页面；只有双击、按下 `Enter` 或点击工具栏的 `Open`，才会真正激活目标窗口或深入子目录。
- **路径与历史同步**：顶部地址栏实时反映 `MiraHikari\Home` 或 `MiraHikari\Projects` 路径，工具栏的 `Back`、`Up`、`Properties` 与 `Folders` 按钮让访客像浏览本地目录一样探索个人内容。

### 2. MiraHikari — Properties：六标签系统属性表单

`MiraHikari — Properties`（`/about/`）借鉴了经典的系统属性（System Properties）对话框，将完整个人档案收束在六个标签页中：

- **General（常规）**：顶部为带凹陷相框的身份铭牌与领域标签，紧随其后是一排四格作品集概览计数卡（项目、技术栈、荣誉、相册，点击可直达对应面板或应用）。下方依次排布个人简介与近况、三条作品导览路径（Web 与云端产品、桌面与硬件工具、黑客松与新交互实验，点击项目胶囊即可跨标签页精准定位到对应项目），以及附带古希腊语铭文（`ἄπειρον`、`καιρός`、`ἔκστασις`）的三条个人原则。
- **Projects（项目档案）**：采用左列表、右详情的主从视图（Master-Detail）替代重复堆砌的八张大卡片。顶部工具栏由纯领域模型 `ProjectBrowser` 驱动，支持中英文及全角字符归一化的关键词搜索、技术标签筛选与排序切换（精选顺序、最新优先、名称排序），并在极窄窗口下自动合并为单一文档滚动区。
- **Journey（经历与时间轴）**：汇集社团与竞赛团队经历、教育背景（示例市第一中学示例班级等），以及从 2021 年入门 Web 开发到 2026 年 AI 时代思考的六段里程碑，通过像素时间轴轨道与技术栈标签串联起完整的成长脉络。
- **Honors（荣誉与认证）**：顶部状态栏汇总国家级、省级与市级奖项分布，下方按分级徽章展示七项竞赛与开源荣誉（含现场或证书原件预览，点击可直接送入 ACDSee 检视）及示例云平台高级云架构工程师认证。
- **Photos（精选印相表）**：以联系印相表（Contact Sheet）网格呈现带编号与分类徽章的精选摄影，连接完整相册与图像查看器。
- **Contact（联络与友链）**：提供邮箱一键复制（含无剪贴板权限时的自动全选输入框回退）、符合 RFC 2426 的 UTF-8 vCard 3.0 `MiraHikari.vcf` 电子名片下载、带分段计量条的语言能力说明，以及带域名徽章的友链名录。

### 3. Device Manager：技术栈设备管理器

`Device Manager`（`/skills/`）将 8 组、56 项技术工具与 5 项正在学习的方向建模为硬件设备树。访客可以使用方向键展开或折叠分类、通过 `Ctrl+F` 搜索关键词（清空搜索时自动恢复此前的展开状态与焦点项），并在右侧摘要面板中查看分段式熟练度计量条、实践年限与笔记详情。

## 640 × 360 与自适应桌面

经典桌面采用 640 × 360 的逻辑画布。自动分辨率模式会结合可用空间调整工作区，让大屏幕容纳更多窗口；小屏幕仍可以使用经典布局、缩放和移动视野。窗口、图标与命中区域都使用整数坐标，视觉位置和点击位置来自同一份几何信息。

桌面图形沿用十六色调色板、像素边框、阈值文字和抖动。系统内置七套主题方案（如 `MHK10 Standard`、`Singularity Night`、`The Void`、`Hot Dog Stand`、`Teal Dream`、`Blue Ribbon` 以及将画布与内嵌网页实时量化为四级绿显的 `Phosphor`），构建脚本从同一份 `THEMES` 表生成 `/themes.css`，确保 Canvas 外壳与 HTML 窗口不会出现色值漂移。

英文界面控件使用由原始字体生成的 1-bit 位图字形；中文正文与个人内容使用本地打包的 12px `MHK CJK`（基于 Fusion Pixel Font），在整数像素字号下保持笔画清晰。照片默认保留源图色彩，用户可以选择十六色预览；切换预览、缩放或旋转不会改写原始图片。

## 一份注册事实

每个 Canvas 应用在实现旁维护零导入的纯数据注册文件（`*.registration.ts`），声明应用标识、名称、公开路由、图标、窗口默认尺寸、开始菜单分类、支持的文件类型和运行别名。构建脚本汇总这些文件，生成不依赖浏览器的应用目录快照。HTML 应用在同一目录体系中声明路由与窗口策略。

开始菜单、桌面默认快捷方式、运行命令、控制面板项、文件关联候选和应用图标都从这份目录派生。运行时还会核对 Canvas 实现与目录是否严格一致，避免有入口却没有程序，或实现存在但未纳入目录的情况。

## 桌面就是一个文件夹

桌面上的应用入口是真正的快捷方式文件，目标指向注册应用。访客创建的文本、文件夹和快捷方式也进入同一套本地文件系统。因此，在文件管理器的 Desktop 文件夹中重命名或删除一个入口，桌面上会出现同样的变化；删除的内容可以从回收站还原。

文件管理器支持前进、后退、上一级、按名称／类型／大小排序，以及创建文件夹、复制、剪切、粘贴和移动。桌面与文件夹之间的拖放使用共同规则：同卷默认移动，跨卷默认复制；Ctrl 指定复制，Shift 指定移动，Alt 或 Ctrl+Shift 创建快捷方式。目录不能拖进自身或子目录。

“我的文档”属于访客自己的浏览器。“个人内容”是随站点发布的只读资料，可以查看或复制为自己的文件，但不能改写发布原件。系统默认快捷方式只在初始化或旧存档迁移时建立；已经删除的入口不会因为刷新页面再次出现。

## 阅读与图片

Reader 负责长文的目录、阅读位置、查找、书签、高亮、笔记和导出。读者可以在像素字体与平滑字体、连续滚动与分栏翻页（`Pages`）、专注模式（`F9`）之间切换，也可以随时按下 `Ctrl+K` 唤起 `Jump To` 面板，在章节标题、书签、笔记与阅读命令之间快速跳转。底栏显示的字数与预计剩余阅读时间基于正文字符数与当前位置计算，切换字号、版式或添加批注不会改变原文统计。发布文章保留独立页面；本地文本和 Markdown 也可以通过“打开方式”进入阅读器。

ACDSee 负责查看图片、按目录筛选、缩放拖拽、旋转、翻转、亮度／对比度／饱和度调节、幻灯片播放和原图下载。示例市创客聚会 2026 游记的 44 张照片继续保留原有图注、拍摄时间与图片文件。文章中的图片链接、个人属性页与相册共享统一的媒体目录（87 张去重媒体记录），避免同一张照片在不同窗口里变成互不相关的副本。

## 叙事、声音与 P(doom) 语域下沉

除了个人作品集与日常小工具，桌面还承载了一条可重玩的权限审查叙事。任务栏右下角的系统时钟在低风险阶段显示真实的本地时间；随着访客在 `Recovery Console`、`train.exe` 与审查流程中做出明确选择，`P(doom)` 风险读数上升，系统会沿着前文所述的五层语域逐步“下沉”：

- **5%（日常阶段）**：完整的 L2 Chicago GUI，时钟显示真实时间，回形针助手在工作区边缘提供上下文提示。
- **34%（夜间阶段）**：主题切换为 `Singularity Night`，系统时钟开始向午夜 `11:57 PM` 漂移。
- **61%（接管阶段）**：`Recovery` 与 `Diagnostics` 窗口退化为 L1 文本终端外框，部分高风险应用入口被锁定。
- **86%（迫近阶段）**：主题进入 `The Void`，屏幕保护程序锁定为 `P(DOOM).SCR`，磁盘整理程序中的块阵列出现自发扰动。
- **99.9%（终局阶段）**：若选择完全移交权限，整个桌面退化为 **L0 固件控制台**（`FIRMWARE CONSOLE`），任务栏压缩为单行状态栏，仅保留 `F1–F4` 键盘指令用于查阅状态、浏览与导出本地文档或重开审查。

声音系统同样基于 Web Audio API 实时合成 PC 扬声器方波与三角波音序，不依赖外部音频文件；`Sound Recorder` 可以直接录制系统发出的音序事件并保存为本地文档。最关键的边界在于：**无论虚构叙事走到哪一步，访客保存在本地的文档以及站点发布的个人资料都始终完好无损、随时可读可导出**。

## 键盘和焦点

键盘操作围绕当前窗口展开。Ctrl+Tab 切换窗口，Ctrl+F4 关闭当前窗口，Alt+F2 打开运行对话框，Ctrl+Shift+Esc 打开任务管理器，Ctrl+Alt+D 显示桌面。菜单和右键菜单也支持完整的方向键、Home/End 与 Escape 导航。

文件管理器可用 Alt+方向键导航，Ctrl+Shift+N 新建文件夹，F2 重命名，Delete 放入回收站，Ctrl+C／X／V 操作剪贴板。输入文件名时，这些按键首先交给文本输入框；打开菜单或对话框后，下面的文件列表不会同时执行操作。

HTML 窗口保留原生文字选择、表单和可聚焦控件，桌面层只接管明确属于窗口管理的命令。触屏设备另外提供屏幕键盘与触控辅助栏，操作仍经过同一套应用输入接口。

## 保存与生命周期

本地文件和偏好保存在浏览器存储中，图片等二进制内容通过浏览器资产存储管理。存储不可用或写入失败时，当前会话仍可保留副本，但界面不会把它标记成可靠的持久保存；需要保留的内容可以导出为 JSON 或 Markdown 备份。

关闭窗口会先处理已经接受的输入和进行中的保存，再决定是否能够关闭。重放剧情与重置文档是不同操作。旧存储键保持兼容，文件写入检查版本，迟到的异步回调不能覆盖重置或重新挂载后的新会话状态。

核心文件、文档、阅读位置、项目筛选和剧情逻辑均为纯领域模型（`*-model.ts`），接受外部依赖注入而不直接访问浏览器全局对象。浏览器适配层负责存储、下载与窗口通信；每个应用会话通过 `createLifetime` 与 `claimSurface` 管理自己的计时器、观察器、事件监听器和临时对象 URL，确保窗口关闭、初始化失败和重复挂载时都能幂等释放资源并恢复初始 DOM 属性。

本地保存不等于所有操作都没有网络请求：打开公开页面或图片会加载站点资源，使用自行配置的 AI 连接时，请求只会在用户明确开启连接后发送到所选择的服务。

## 构建与验证

项目使用 Astro 和 TypeScript，以静态站点形式构建。文章正文由内容集合管理，标题、摘要、发布日期和修订日期用于页面、RSS 与站点地图。每个公开内容页面具有独立的 canonical 地址、JSON-LD 结构化数据、分享元数据和语义化结构；内部应用页面与已撤下文章的兼容跳转带有 `noindex` 并指向规范地址，不进入内容索引。

集成校验（`npm run verify`）包含以下完整门禁：

- **静态与架构门禁**：TypeScript 类型诊断、ESLint 代码检查、Prettier 格式校验，以及基于 `dependency-cruiser` 的架构规则（强制检查注册文件零导入、纯领域模块零宿主依赖、图形层与应用层单向依赖、无运行时循环依赖）。
- **单元与接口测试**：覆盖文件系统冲突恢复、阅读器笔记本合并与文本统计、项目与技能树检索模型、vCard 折叠编码、启动序列时序与生命周期隔离。
- **构建与站点审计**：生产构建后自动扫描全部生成页面的本地资源引用、canonical 链接、面包屑与文章结构化数据、RSS 及 Sitemap 完整性。
- **真实浏览器端到端场景**：基于 Playwright Chromium（桌面与移动端视口），按逻辑坐标向 Canvas 发送真实键鼠输入，并验证混合窗口遮挡、无脚本回退、极小窗口可达性、剪贴板失败降级与会话重挂载资源零泄漏。
